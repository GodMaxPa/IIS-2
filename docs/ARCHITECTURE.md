Один мод `iis` (корневой пакет `ru.iis`). Делим на отдельные JAR только при реальной необходимости.

## Два пути
Общая «экономика» — материалы, формы и теги (`core`). Индустрия (`machine`, `energy`, ...) и биопуть (`bio`) друг друга не импортируют; гибриды — только в `ru.iis.duo` (Дуо, D41), который зависит от обоих и о котором ядро не знает. Прогрессия проверяет теги уровня материала, а не конкретные предметы (D37).

## Генерируемые файлы
`python3 -I tools/gen/gen_content.py` пересоздаёт `src/generated/resources/` (включая датапак `packs/iis_overrides`) и `src/main/resources/iis/*.json` из `reference/original/`. Руками эти файлы не править. Отдельного Java-datagen нет: генераторы — Python-скрипты `tools/gen/*.py` (D14); рецепты химии GT5 переносятся автоматически (`extract_gt5_recipes.py` → `chem.py`, D76). Локально нужен клон текстур GT5 (`IIS_GT5_TEXTURES`, см. HANDOFF); био-ресурсы — `python -I tools/gen/bio.py`. Книга квестов ИИС 1 — `python -I tools/gen/quests.py` после `gen_content.py` → `quests/ftbquests` (копируется в `<игра>/config/ftbquests/quests`, D101).

## Принципы
1. **Логика отдельно от Minecraft.** Расчёты (энергия, разгон, рецепты, структуры) — обычные Java-классы с unit-тестами.
2. **Данные отдельно от кода.** Материалы, рецепты, жилы — через datagen/JSON, чтобы балансировать без переписывания логики.
3. **Поведение, а не устройство.** MetaTileEntity с числовыми ID из GT5 не переносим: блок-сущности, data components, data-driven рецепты NeoForge 26.1.

## Проверка
- `src/test` — JUnit 5, без запуска игры.
- GameTest (`ru.iis.gametest`, `gradlew runGameTestServer`): машины, сети и места Био в реальных тиках (D33).
- Стендовый мир (`scripts\stand.ps1`, `/iis stand`): всё содержимое в работе; игровой тест `stand_world_works` (D74).
- `scripts/smoke-server.sh` — реальный выделенный сервер: проверяет загрузку мода и команды (рассчитан на Linux/облако).
- Клиент проверяет владелец по чек-листу среза.
