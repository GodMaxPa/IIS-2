# Архитектура

Один мод `iis` (корневой пакет `ru.iis`). Делим на отдельные JAR только при реальной необходимости.

## Пакеты

| Пакет | Назначение | Состояние |
|---|---|---|
| `ru.iis` | Точка входа `IIS`, подключение подсистем | ✅ есть |
| `ru.iis.energy` | Напряжения, EU, кабели, сети | 🟡 только `VoltageTier` |
| `ru.iis.machine` | Машины, обработка рецептов, разгон | 🟡 только `Overclock` |
| `ru.iis.command` | Служебные команды (`/iis`) | ✅ есть |
| `ru.iis.core` | Материалы, формы предметов, реестры | ⏳ срез 2 |
| `ru.iis.recipe` | Типы рецептов GT как данные | ⏳ |
| `ru.iis.world` | Рудные жилы, геологоразведка | ⏳ срез 2 |
| `ru.iis.multiblock` | Многоблочные структуры | ⏳ срез 5 |
| `ru.iis.rail` | Железная дорога | ⏳ |
| `ru.iis.space` | Космос | ⏳ |
| `ru.iis.equipment` | Броня, оружие, транспорт | ⏳ |
| `ru.iis.compat` | JEI/EMI, Jade и т.п. (необязательные) | ⏳ |
| `ru.iis.datagen` | Генерация JSON: рецепты, модели, теги, переводы | ⏳ |

## Принципы
1. **Логика отдельно от Minecraft.** Расчёты (энергия, разгон, рецепты, структуры) — обычные Java-классы с unit-тестами.
2. **Данные отдельно от кода.** Материалы, рецепты, жилы — через datagen/JSON, чтобы балансировать без переписывания логики.
3. **Поведение, а не устройство.** MetaTileEntity с числовыми ID из GT5 не переносим: блок-сущности, data components, data-driven рецепты NeoForge 26.1.

## Проверка
- `src/test` — JUnit 5, без запуска игры.
- `scripts/smoke-server.sh` — реальный выделенный сервер: проверяет загрузку мода и команды.
- Клиент проверяет владелец по чек-листу среза.
